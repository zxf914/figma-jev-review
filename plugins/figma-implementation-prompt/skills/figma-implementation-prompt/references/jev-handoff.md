# Figma Jev Review 交接

只有当前环境提供 `figma_jev_review`，或用户明确要求 Jev 评审时，才在实现提示词中增加本参考定义的章节。

## 验收契约

在“验收清单”前增加：

```markdown
## Figma Jev Review 验收契约

| ID | 类别 | 严重程度 | 要求 | 依据 | 验证方法 |
|---|---|---|---|---|---|
```

字段规则：

- ID 使用稳定前缀：布局 `LAY`、视觉 `VIS`、字体 `TYP`、资源 `AST`、交互 `INT`、响应式 `RSP`、工程质量 `QUA`。
- 严重程度使用 `blocking`、`required` 或 `scored`。
- 要求必须能观察或测量，不能只写“与设计一致”。
- 依据使用本 Skill 已定义的来源标签，并包含 Figma 节点 ID 或项目文件路径。
- 验证方法写明截图比较、DOM 测量、源码检查、浏览器交互、控制台检查或自动化测试。

影响页面可运行性、核心视觉、原始资源来源、明确业务行为或正式文件可靠性的项目使用 `blocking`。重要但不使整个结果无效的项目使用 `required`。允许按偏差程度判断的质量项目使用 `scored`。

## 视觉运行矩阵

按已确认的平台、视口和关键状态生成：

```markdown
## Figma Jev Review 验证矩阵

| 视口或设备 | 页面状态 | 到达操作 | 需要记录的截图 | DOM/溢出检查 | 控制台检查 |
|---|---|---|---|---|---|
```

Figma 没提供且项目也没有规范的视口或状态不能自行补造。缺失内容仍按不确定项规则处理。

## 实现阶段交接

提示词要求实现者：

1. 完成页面和正常项目验证。
2. 为验收契约中的每项记录 `passed`、`failed` 或 `unknown` 以及实际证据。
3. 对验证矩阵逐项运行页面，记录截图路径、实际比较结论、测量值和控制台错误。截图路径本身不是 Jev 可读取的证据。
4. 只提供当前差异和判断所需文件，调用 `figma_jev_review` 建立基线。
5. 根据重要弱项检查真实原因，做最小修改，重新运行受影响的验证。
6. 携带上一次完整结果作为 `previousEvaluation` 复评。

Jev 分数不能覆盖失败或未知的 `blocking` 项，也不能代替本地视觉验证。
