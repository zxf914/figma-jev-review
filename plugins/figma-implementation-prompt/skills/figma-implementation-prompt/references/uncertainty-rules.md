# 不确定项规则

## 依据标签

每个关键结论只能归入以下一种来源：

- `[Figma 精确值]`：节点属性直接提供的尺寸、位置、文本、颜色、字体或状态。
- `[截图视觉判断]`：截图能确认，但结构化数据没有完整表达。
- `[项目现有实现]`：当前项目真实存在的组件、样式或交互，并注明文件位置。
- `[用户已确认]`：用户在当前任务明确给出的决定。
- `[需要用户确认]`：缺少可靠依据且不同选择会改变视觉、交互、数据模型或验收结果。

## 必须阻塞正式文件

以下内容在 Figma 和项目中都没有依据时必须询问：

- 单选、复选、分页、按钮等控件的关键状态样式
- 长文本换行、省略、Tooltip、展开、最大行数和容器高度
- 示例数量之外的数据采用滚动、分页、轮播、展开还是截断
- 删除确认、批量选择、跨页选择和新增表单等业务行为
- 地图弹窗避让、多个弹窗、点位选中和隐藏状态的业务条件
- 轮播列表的选中锚点、暂停、恢复、循环、持续时间和缓动
- App 平台、单位、安全区域、导航或键盘处理无法从项目判断
- Figma 视觉资源无法导出或下载、导出结果缺层、资源边界不明确，且项目中没有视觉一致的现有资源
- 资源节点或其父级的透明度、裁切、缩放、偏移、混合模式、滤镜、遮罩或叠放关系无法读取，且差异会明显改变最终视觉

不得先选择一种做法，再把问题放到正式文件末尾。不得用“推荐默认值”“低风险假设”或“方便后续替换”绕过确认。
不得把手写 SVG、CSS 图形、Canvas 或近似图标作为资源获取失败后的默认降级方案；只有用户明确授权代码重绘后才能采用。

## 可以直接继承

项目已有同类组件时，其 hover、focus、disabled、加载、空状态和可访问性行为可以直接复用，并记录组件路径。纯实现组织方式且不改变页面结果的细节可以由实现者决定。

## 提问方式

先完成所有不依赖答案的读取和项目扫描，再集中提出同一页面的阻塞问题。每题说明：缺失依据、受影响区域、可选方案及差异。推荐项可以说明理由，但不能视为用户已经选择。
