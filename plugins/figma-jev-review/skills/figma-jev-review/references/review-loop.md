# 评审循环

## 首次评审

页面形成完整可运行版本并完成相关验证后调用 `figma_jev_review`。首次结果是基线，不是交付结论。

按以下顺序处理结果：

1. 修复 `blocked` 中失败或未知的阻塞项。
2. 修复失败或未知的 `required` 检查。
3. 检查优先项中最低且影响需求的指标。
4. 根据代码和证据形成具体原因假设。
5. 做最小改动，重新执行原验证。
6. 传入当前实现和上一次完整 `previousEvaluation` 复评。

目标指标没有提高时，重新检查原因假设。不能随机修改样式、拆文件或增加抽象来追分。

## 停止条件

同时满足以下条件时停止：

- 所有 `blocking` 和 `required` 检查通过。
- 所有核心视觉指标均适用且置信度不低于 `0.8`。
- 参考图与实现图均成功读取，尺寸一致，差异没有超过各视觉运行的阈值。
- 项目正常测试和浏览器验证通过。
- 重要目标指标已经改善，且没有引入有意义的退步。
- 剩余低分或低置信度项没有具体且符合需求的改进措施。

正确性、用户要求和可复现的本地验证始终高于 Jev 分数。
